**TL;DR:** Beide Bugs haben die gleiche Root Cause — ein Crash in `PatternEngine.generate()` durch den Phase-4-Refactor.

## 🔍 Root Cause

In Phase 4 wurde `PatternEngine.generate()` umgebaut: `applyMood()` wird **pro Track** einzeln aufgerufen, mit single-track Patterns wie `{ drums: {...} }`.

```javascript
// PatternEngine.generate() — pro Track:
const trackRaw = { [track]: raw[track] };
const mooded = applyMood(effectiveMood, trackRaw, genreWeights, seed);
```

Aber `applyMood()` und alle Sub-Funktionen (`applyDensity`, `applyComplexity`, `applyDarkness`, `applyEnergy`, `applyWeirdness`) erwarten **ALLE drei Tracks** im Pattern-Objekt:

```javascript
// applyDensity() — crasht hier:
drums = Object.entries(patterns.drums);   // undefined wenn track='bass'
bass = applyMelodicDensity(patterns.bass); // patterns.bass undefined → .notes.map() → 💥
synth = applyMelodicDensity(patterns.synth);
```

`TypeError: Cannot read properties of undefined (reading 'notes')`

## 💥 Was passiert konkret

| Szenario | Wo passiert's | Ergebnis |
|----------|--------------|----------|
| **Internal Clock Play** | `generatePattern()` hat try-catch → fängt Error | **Fallback-Pattern** (simple 4/4 Kick) wird gespielt. MIDI kommt, aber ignoriert ALLE Parameter |
| **Internal Clock Live-Update** | `useEffect` hat try-catch → fängt Error | `console.warn`, `loadPatternLive` wird nie aufgerufen → **keine Parameter-Änderung hörbar** |
| **External Clock Play** | `onStart` handler hat **KEIN** try-catch → uncaught | Error killt MIDI-Message-Handler, `scheduler.start()` + `startExternal()` werden nie erreicht → **keine Noten** |

## 🛠️ Fix (2 Änderungen)

### Fix 1: `PatternEngine.generate()` — Safe Pattern Wrapper

Statt `trackRaw = { [track]: raw[track] }` → vollständiges 3-Track-Objekt mit leeren Defaults für die nicht-aktuellen Tracks bauen:

```javascript
// Vor applyMood: sicheres 3-track Objekt
const emptyDrums = { kick: a16(0), snare: a16(0), hihat: a16(0), clap: a16(0), perc: a16(0) };
const emptyMelodic = { notes: a16(0), gate: a16(0) };

const safePattern = {
  drums: track === 'drums' ? (raw.drums || emptyDrums) : emptyDrums,
  bass:  track === 'bass'  ? (raw.bass  || emptyMelodic) : emptyMelodic,
  synth: track === 'synth' ? (raw.synth || emptyMelodic) : emptyMelodic,
};
const mooded = applyMood(effectiveMood, safePattern, genreWeights, seed);
```

`applyMood` arbeitet auf allen drei Tracks, aber nur der aktuelle hat echte Daten → kein Crash, korrekte Per-Track-Mood-Overrides.

### Fix 2: `App.jsx` — Try-Catch in `onStart`/`onContinue`/`onClock`

External-Clock-Pfade absichern, analog zu `generatePattern()`:

```javascript
// onStart, onContinue: patternEngine.generate() in try-catch wrappen
try {
  const pattern = patternEngine.generate(...);
  scheduler.start(pattern, ...);
  scheduler.startExternal(pattern, ...);
} catch (e) {
  console.warn('External clock pattern error:', e);
  const fallback = generateFallbackPattern();
  scheduler.start(fallback, ...);
  scheduler.startExternal(fallback, ...);
}
```
