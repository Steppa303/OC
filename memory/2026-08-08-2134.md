# 🩺 BeatGen — Pattern Generation Audit

## Executive Summary

Deine Pattern-Engine hat drei kritische Bugs und ein fundamentales Architekturproblem, das die ganze "Global Mood → Per-Track Override" Logik aushebelt. Von den 16 Per-Track-Parametern funktionieren effektiv **nur 3-4 korrekt**. Die anderen sind entweder Stubs ohne Code, kaputt, oder überschreiben Werte die sie nicht überschreiben sollten.

---

## 🔴 CRITICAL: Default-Override zerstört Global-Mood-Chain

**Symptom:** Global-Mood-Drehregler (Master) haben kaum/keine Auswirkung, sobald die Per-Track-Panels existieren.

**Root Cause:** In `PatternEngine.generate()`:

```javascript
const effectiveMood = { ...moodParams };
if (tp.density !== undefined) effectiveMood.density = tp.density;
if (tp.complexity !== undefined) effectiveMood.complexity = tp.complexity;
// etc.
```

Die Per-Track-Parameter starten alle bei **50** (default). Der Check `tp.density !== undefined` ist IMMER true — also überschreibt JEDE Spur die globalen Mood-Werte mit 50. Wenn du Global Density auf 80 drehst, passiert **nichts**, weil alle drei Tracks hart auf 50 overriden.

**Das ist der Hauptgrund warum "manche Slider keine Auswirkung haben."**

**Fix:** Per-Track-Parameter brauchen einen "inherit"-State. Default sollte `null`/`undefined` sein, nicht 50. Nur wenn der User den Per-Track-Regler ANFASST, wird der Wert gesetzt und überschreibt Global. Z.B. durch einen "Auto"/"Global"-Toggle pro Parameter oder durch `null` als Default:

```javascript
// Store-Defaults:
trackParams: {
  drums: { density: null, complexity: null, groove: null, ... },
  bass:  { density: null, complexity: null, groove: null, darkness: null, ... },
  // ...
}

// Engine:
if (tp.density != null) effectiveMood.density = tp.density; // Nur override wenn explizit gesetzt
```

UI-seitig: Wenn `null` → Knob zeigt Global-Wert (disabled/grau) + Label "Auto". Erstes Antippen/Drehen setzt den Wert explizit.

## 🔴 CRITICAL: Drum Weights tun NICHTS

**Symptom:** Kick/Snare/Hihat/Clap/Perc-Weight-Slider im DrumMixPanel haben null Effekt.

**Root Cause:** `PatternEngine._applyDrumWeights()`:

```javascript
_applyDrumWeights(drumPattern, tp) {
  const weights = { kick: tp.kickWeight ?? 100, ... };
  // Drum weights act as probability multipliers — no change at 100%
  // For now, weights don't change active steps
  return drumPattern; // ← MACHT NICHTS
}
```

Die ganze Funktion ist ein Stub. Die Werte werden gespeichert, der UI-Slider bewegt sich, aber der Drum-Pattern-Mix ignoriert sie komplett.

**Fix:** Die Weights müssen in die `GenreMixer.mixDrumPattern()` rein oder als Post-Processing auf `buildDrumSteps()`. Einfachster Ansatz: aktive Drum-Hits mit `weight/100` Wahrscheinlichkeit behalten/entfernen.

## 🔴 CRITICAL: Chord Mode kaputt

**Symptom:** Chord Mode (Off/2-Note/3-Note) tut nichts.

**Root Cause:** In `_applyMelodicParams()`:

```javascript
if (chordMode !== 'off') {
  // Baut chordSteps Array mit extra Noten...
  // ...und verwirft es dann KOMPLETT:
  steps = melodicPattern.steps.map(step => {
    // ← Das ist der ORIGINAL-Pattern, keine Chords!
    return { ...step, note };
  });
}
return { steps };
```

Der Code kommentiert selbst "Better approach: keep 16 steps", "Actually, for simplicity...", und endet damit, dass er die Chord-Logik komplett wegwirft und das Original-Pattern returned.

**Fix:** Chord-Mode muss fertig implementiert werden. Entweder:
- Echte Polyphonie im Step-Format (array von notes pro step statt single note)
- Oder Chord-Noten als separate MIDI-Events mit gleichem Timing aber versetzten Notes
- MidiMapper + MidiScheduler müssen dann mehrere Notes pro Step unterstützen

## 🟡 MAJOR: Note Length ist irreführend

**Symptom:** "Note Length" Slider ändert die Velocity statt der Tondauer.

**Root Cause:** `_applyMelodicParams()`:

```javascript
if (noteLength < 50) {
  velocity = Math.round(velocity * (0.5 + noteLength / 100));
} else if (noteLength > 50) {
  velocity = Math.min(127, Math.round(velocity * (0.75 + noteLength / 200)));
}
```

Das ist ein Velocity-Modifier, kein Note-Length/Gate-Time-Modifier. Für einen Nutzer heißt "Note Length 20%" → kurze Staccato-Noten, nicht "leisere Noten".

**Fix:** MidiMapper müsste Note-Off-Events nach `(stepDuration * noteLength/100)` ms senden statt am Ende des Steps. Dafür braucht der Scheduler Gate-Time-Support pro Step.

---

## 🟡 MAJOR: Velocity Curve ignoriert Per-Track-Parameter

**Symptom:** Per-Track-Darkness/Energy haben keinen Einfluss auf die Velocity der einzelnen Spur.

**Root Cause:** In `generate()`, Schritt 4:

```javascript
// Verwendet GLOBALE moodParams, nicht effectiveMood pro Track
const velocityCurve = applyMoodToVelocityCurve(baseCurve, moodParams, seed);
pattern = applyVelocityCurve(pattern, velocityCurve);
```

Alle drei Spuren kriegen die gleiche Velocity-Curve basierend auf globalen Mood-Werten. Wenn du Per-Track-Darkness auf 100% drehst und willst dass der Bass softer gespielt wird — Pech gehabt.

**Fix:** Velocity-Curve muss pro Track mit den effective-Mood-Werten berechnet werden, nicht einmal global.

## 🔧 Empfohlene Fixes (priorisiert)

### Fix 1: Per-Track "Inherit from Global" (1h) ← Höchste Prio
- Store: `null` als Default für Density/Complexity/Groove/Darkness/Weirdness
- Engine: `if (tp.density != null)` statt `!== undefined`
- UI: Knobs/Sliders zeigen Global-Wert wenn `null`, visuelles "Auto"-Label, erster Touch setzt Wert

Das fixt SOFORT das Problem dass Global-Mood-Knobs "keine Auswirkung" haben.

### Fix 2: Drum Weights implementieren (1h)
- In `mixDrumPattern()` oder in `_applyDrumWeights()`: aktive Drum-Hits mit `weight/100` Wahrscheinlichkeit filtern
- ODER: Als Post-Processing im `buildDrumSteps()` die Wahrscheinlichkeit der Hit-Priorität anpassen

### Fix 3: Chord Mode fertig bauen (2h)
- `buildMelodicSteps()` so erweitern dass es mehrere Notes pro Step unterstützt
- MidiMapper: pro Step mehrere Note-On-Events senden
- Velocity für Chord-Noten: 70% der Root-Note-Velocity

### Fix 4: Velocity Curve per-Track (1h)
- `applyMoodToVelocityCurve()` pro Track mit `effectiveMood` aufrufen statt einmal global

### Fix 5: Note Length → Gate Time (2-3h)
- Step-Format um `gateTime` erweitern (in ms oder % von Step-Duration)
- MidiScheduler: Note-Off nach `gateTime` statt am Step-Ende
- Größerer Umbau, aber dann funktioniert Staccato/Legato wirklich

## 🎯 Empfehlung für intuitive UX

Nach den Fixes sollte das Verhalten so sein:

1. **Global Mood (Master)** → Setzt die Baseline für ALLE Spuren
2. **Per-Track-Regler auf "Auto"** → Folgen dem Global-Mood-Wert
3. **Per-Track-Regler angefasst** → Überschreibt Global für DIESE Spur
4. **Reset auf "Auto"** → Ein Doppelklick/Reset-Button pro Parameter

Das ist das intuitive Modell: "Ich dreh Global Darkness hoch → alles wird düsterer. Aber der Synth soll bright bleiben → ich dreh Synth Darkness runter."

Im aktuellen Zustand ist das genau umgekehrt: Alle Tracks blockieren Global, und du musst JEDEN Track einzeln anpassen.
