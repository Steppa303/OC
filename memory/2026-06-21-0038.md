## Current State Analysis

The ReaderView component currently implements a basic swipe gesture using Framer Motion's drag API:

```javascript
const handleDragEnd = useCallback((_e: MouseEvent | TouchEvent | PointerEvent, info: PanInfo) => {
  const threshold = 80
  if (info.offset.x < -threshold) {
    nextChapter()
  } else if (info.offset.x > threshold) {
    prevChapter()
  }
}, [nextChapter, prevChapter])

// In the motion.div for content:
drag="x"
dragConstraints={{ left: 0, right: 0 }}
dragElastic={0.2}
onDragEnd={handleDragEnd}
```

**Issues identified:**
1. `dragConstraints={{ left: 0, right: 0 }}` effectively disables horizontal dragging (0px allowed in each direction), making the gesture non-functional.
2. No visual feedback during drag - users don't see preview of adjacent chapters.
3. Binary threshold (80px) without spring-based snapping feels less polished.
4. Only renders current chapter; no pre-loading of adjacent chapters for smooth transitions.

## Proposed Solution

Implement a robust swipe navigation with:
- Visual chapter preview during drag (showing peeking of next/previous chapter)
- Spring-based snapping to next/chapter when drag exceeds 50% width threshold
- Proper drag constraints allowing full horizontal movement with elastic boundaries
- Performance optimization through chapter pre-loading
- Fallback for non-touch devices (keyboard/mouse)

## Implementation Steps

### 1. Chapter Pre-loading & Rendering
Modify ReaderView to render three chapters simultaneously:
- Previous chapter (offset: -100%)
- Current chapter (offset: 0%)
- Next chapter (offset: +100%)
All wrapped in a container with `overflow: hidden` and `position: relative`.

### 2. Drag State Management
Introduce drag offset state using Framer Motion's `drag` and `onDrag` events:
```javascript
const [dragX, setDragX] = useState(0)
// or use Framer Motion's drag constraints with a ref
```

### 3. Enhanced Drag Constraints
Set constraints to allow full chapter width movement:
```javascript
dragConstraints={{ 
  left: -chapterWidth, 
  right: chapterWidth, 
  top: 0, 
  bottom: 0 
}}
```
Where `chapterWidth` is measured via `useResizeObserver` or `getBoundingClientRect`.

### 4. Visual Feedback During Drag
Translate chapter container based on dragX:
```javascript
style={{ 
  transform: `translateX(${dragX}px)`,
  transition: dragX === 0 ? 'transform 0.2s ease' : 'none'
}}
```

### 5. Chapter Transition Logic
On `dragEnd`:
- If `dragX < -chapterWidth * 0.5`: snap to next chapter
- If `dragX > chapterWidth * 0.5`: snap to previous chapter
- Else: snap back to current chapter
Use Framer Motion's `animate` prop with spring configuration for natural motion.

### 6. Chapter Index Updates
After snap animation completes:
- Update `currentChapterIndex` in reader store
- Reset dragX to 0
- Pre-load adjacent chapters (if not already loaded)

### 7. Accessibility Considerations
- Maintain keyboard navigation (arrow keys)
- Reduce motion preference respect
- Screen reader announcements for chapter changes
- Touch action manipulation CSS for better touch handling

### 8. Performance Optimization
- Use `useMemo` for chapter content rendering
- Implement chapter loading based on proximity (load n chapters ahead/behind)
- Debounce rapid drag events
