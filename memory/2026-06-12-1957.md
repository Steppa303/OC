### 🔧 Technische Implementation

#### Backend — neuer Endpoint

**`GET /api/models/openrouter`**

```typescript
// Proxy zu OpenRouter API
const OR_URL = 'https://openrouter.ai/api/v1/models';

app.get('/api/models/openrouter', requireAuth, async (req, res) => {
  const response = await fetch(OR_URL);
  const data = await response.json();
  
  // Filter: nur Text-generating models, deduplizieren
  const models = data.data
    .filter(m => m.architecture?.modality?.includes('text->text'))
    .map(m => ({
      id: m.id.replace(/:free$/, ''),           // Strip :free suffix
      slug: m.id,
      name: m.name.replace(/\s*\(free\)$/, ''),  // Clean name
      context_length: m.context_length,
      pricing: m.pricing,
      description: truncate(m.description, 120)
    }))
    .sort((a, b) => a.id.localeCompare(b.id));
  
  res.json({ models, total: models.length });
});
```

**Warum Backend-Proxy:**
- OpenRouter API Key bleibt server-side (auch wenn List-Endpoint public ist, safe is safe)
- Caching möglich (in-memory, 5min TTL)
- Filtern/Vorverarbeiten server-side

#### Frontend — Insertion Logic

Die Config wird als JSON-String gemanaged. Der Insert-Prozess:

```typescript
function addModelsToConfig(content: string, selectedModels: OpenRouterModel[]): string {
  const config = JSON.parse(content);
  
  // Ensure path exists
  if (!config.models?.providers?.openrouter?.models) {
    throw new Error('models.providers.openrouter.models not found in config');
  }
  
  const existingIds = new Set(
    config.models.providers.openrouter.models.map((m: any) => m.id)
  );
  
  const newEntries = selectedModels
    .filter(m => !existingIds.has(`openrouter/${m.id}`))
    .map(m => ({
      id: `openrouter/${m.id}`,   // ← Das wichtige Prefix
      name: m.name
    }));
  
  config.models.providers.openrouter.models.push(...newEntries);
  
  return JSON.stringify(config, null, 2);  // Pretty-print wie Original
}
```

**Duplikat-Prävention:** Check gegen `existingIds` — wenn `openrouter/deepseek/deepseek-v4-flash` schon existiert, nicht nochmal hinzufügen.

### ⚠️ Edge Cases & Handling

| Case | Handling |
|------|----------|
| Config hat keinen `models.providers.openrouter.models` Pfad | Error Toast + Panel bleibt offen |
| Model bereits vorhanden (Duplikat) | Wird automatisch rausgefiltert |
| OpenRouter API down | Error State im Panel + Retry Button |
| 2000+ Models in der Liste | Client-side search/filter, virtuelles Scrolling nicht nötig (Browser kann 2000 Checkboxen) |
| Sehr viele Models selektiert (>20) | Confirm Dialog: "Add 50 models?" |
| Config wird während Panel offen ist extern geändert | Panel cached models snapshot, beim Add wird current content gelesen |
| Model ID enthält Sonderzeichen | Kein Problem, wird als String in JSON escaped |

**Pricing Formatierung:**
- **Free models**: Badge "FREE" in grün (`text-emerald-400`, kleiner Pill)
- **Paid models**: `$0.15/$0.60M` = Input $0.15/M, Output $0.60/M tokens
- **Sehr billig** (< $0.10/M): gräulich, klein — fällt nicht auf
- **Teuer** (> $5.00/M): leicht orangener touch, small warning vibe
- **Cached Input**: nur anzeigen wenn vorhanden, dann `$0.05/0.15/0.02M` (prompt/output/cached)

**Mobile**: Die Pricing-Zeile wraped bei Bedarf, bleibt aber kompakt auf einer oder max zwei Zeilen.
