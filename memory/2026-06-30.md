# 2026-06-30

## 🍳 AddBook Recipe Pipeline

Bastian wollte einen neuen Trigger "Rezept:" in addbook_sync.py, der automatisch Rezepte aus dem Internet sucht, filtert und als PDF an den Kindle sendet.

### Was gebaut:
- **`addbook/recipes/recipe_search.py`** — DuckDuckGo Rezeptsuche + Schema.org JSON-LD Parsing + Rating-Filter ≥ 4.2⭐
- **`addbook/recipes/recipe_pdf.py`** — WeasyPrint PDF Generator (A5, Coverpage, Zutaten, Steps, Bilder)
- **`addbook/recipes/.recipe_state.json`** — Dedup (nie 2x dasselbe Rezept)
- **`addbook/addbook_sync.py`** — Komplett neugeschrieben: `Buch:` UND `Rezept:` Trigger parallel
- **`addbook/scripts/send-to-kindle.py`** — Jetzt auch PDF-kompatibel

### Format:
```
Rezept: Chicken Tikka Masala 3x
```
→ 3 Rezepte in 1 PDF → direkt an Kindle (kein Telegram-Klick nötig)

### Wichtige Entscheidungen:
- Zwei unabhängige Trigger in einer Datei (Buch + Rezept gleichzeitig möglich)
- Rating-Filter hart bei ≥ 4.2⭐
- Internationale Quellen (DuckDuckGo, kein Chefkoch-Lock-in)
- Multiplier: Suffix `2x`, `3x` etc. → count Rezepte in 1 PDF
- send-to-kindle.py erkennt file extension (.epub vs .pdf) automatisch

### Lessons Learned:
- `duckduckgo_search` wurde zu `ddgs` renamed — pip install ddgs
- ddgs nutzt Bing + Google + andere Engines, nicht nur DuckDuckGo
- Schema.org JSON-LD ist verlässlicher als Microdata/RDFa
- WeasyPrint erzeugt schöne PDFs mit Font-Subsetting
- Rating-count kann als String kommen → int() wrappen

### 🐛 Bugfixes (3 Iterationen):

**Iteration 1 (Commit 0982dff0a):**
- Multi-Line Support: Scribe schreibt `Rezept:` + Query auf nächster Zeile
- Checkmark-Cleaning: `✔` wird entfernt
- Bare Number: `3` ohne `x` wird als Multiplier erkannt

**Iteration 2 (Commit 73cde36bf):**

- PDF-Bilder: Pillow resize auf max 400px + JPEG quality 70
- PDF-Größe von ~500KB auf ~150KB reduziert

**Iteration 3 (Commit 2779bda73 + aktuell):**

- Query-Cleaning: `c.isascii()` Filter für Dateinamen, Subject, Dedup-Key
- Kindle Convert: `[Convert]` im Subject für PDF → Amazon konvertiert automatisch
- State sofort auf `processing` vor Pipeline-Start
